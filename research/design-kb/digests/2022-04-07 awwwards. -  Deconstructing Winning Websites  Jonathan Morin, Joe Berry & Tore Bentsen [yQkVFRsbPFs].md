## Core thesis
A minimal, Swiss-style black site that exists only to let long, slow bike videos shine can win awards because of restraint and many small crafted details (custom cursor, custom video player, page transition), not because of flashy effects. The panel argues Webflow is a good base for designers who do not write JavaScript, as long as they know basic CSS and know when to step outside the tool.

## Claims and advice
- [P][EMO] Project was a passion project started by the maker's friend (the film-maker), with no brief to sell anything; the aim was a "video love story" for the mountain-bike community, intentionally slow and clean vs the usual fast, dirty, rocky MTB site aesthetic. Freedom from a commercial brief allowed focus. (6:08-10:13) — evidence (maker's own account)
- [VIS-L][Q] Black background, simple readable sans-serif, no big red "buy" buttons, no images, only video; the interface should not over-dominate the main asset. Joe: "less is more", the video is the star. (9:11-11:15) — opinion
- [VIS-L] Hero video is cropped to a circle rather than a rectangle, and that shape language repeats through the site; Joe says it adds a unique vibe. (11:15) — opinion
- [VIS-M] Custom cursor is two divs that follow the mouse, animated with GSAP (caption says "Gap tweet max", verify = GSAP/TweenMax); the maker found GSAP smoother than Webflow's native interactions. (12:16)  — practice (tool-dependent)
- [VIS-M][MOB] The blinking-eye animation was done with plain CSS clip-path ellipse (shutter effect) because Webflow interactions overdid it and do not work the same on mobile; basic CSS gave the same effect on hover and on mobile. (13:17) — practice (tool-dependent)
- [Q] Webflow plus video costs performance, so be careful with animation and video; for a video-heavy site, keep the design simple so heavy assets are the only weight. (14:17-16:20) — opinion
- [Q] Compress video carefully: the maker used Adobe Media Encoder and a web compressor (mp4compress.com) "cheat"; Joe prefers HandBrake (caption "Handbreak"), and uses lazy-loading for video via HTML5 embeds rather than Webflow's background video. (16:20-19:22) — practice
- [TOOLS] Custom video player built with Video.js, styled with ordinary CSS by inspecting class names and overriding; videos hosted on Vimeo Pro with direct links (gives 1080/720 renditions and view stats). Inspiration for the player: the "Alan Menken" site by Hello Monday (caption "Alan Menin", verify). (19:22-24:26) — practice (tool-dependent)
- [Q][TOOLS] Videos are managed in Webflow CMS: fields for track name, height meters, kilometers, video time, with the video link pasted into a text field. (24:26-25:27) — practice
- [Q] Sound is off by default because browsers block autoplay audio and a hard page switch resets it; they also argue unexpected sound could blast headphone users. Joe's trick: an "Enter" intro button that unlocks sound, plus an on/off toggle. (25:27-28:29) — practice
- [VIS-M] Page transition: a box 200% of viewport width, half of it a gradient, slides in, then rotates on the next load so it appears to leave the other way; uses a delayed-navigation JavaScript snippet. The maker would now use Timothy Ricks' newer approach that detects internal links automatically so you set it once. (28:29-31:33) — practice (tool-dependent)
- [Q][MOB] iPhone low-power mode blocks autoplaying video and cannot be overridden. (31:33-33:35) — evidence (anecdotal, no workaround found)
- [P] Process: do first art-direction steps in design software, then move into Webflow early; "while you're coding you actually think website". Interaction ideas (e.g. the eye) emerged during build; Joe says design is "90%" done before Webflow but he adjusts in the build and tells clients that after sign-off he may tweak things that work better in context. Maker deleted ideas that do not serve the story; "a website is just a story". (33:35-36:39, 40:46-43:48) — opinion
- [P] Building in the real tool early reveals your limits as a non-developer, so you can adapt ideas to what you can ship. (36:39) — opinion
- [VIS-T][MOB] Responsive type for a poster-style site: everything sized in percentages or viewport width (vw), with min/max clamping for hardcore setups; mobile may switch to rem; Finsweet "fluid responsive" and Timothy Ricks' approach (em relative to viewport width) exist but Joe warns pure fluid scaling should not be on every site and mobile needs more fixed proportions. (37:41-40:46) — opinion
- [Q] Restraint: the maker originally tried skewing and rotating text but removed it because it cost performance and added nothing; Joe's "brilliant basics" idea: simple layout done brilliantly plus small touches of animation; "ask: does this make sense? Is this making it better? If not, remove it." (46:55-48:57) — opinion
- [BIZ][CL] Webflow's value for clients: they can edit video or images themselves without a developer, which builds trust; embrace limitations and decline clients whose needs exceed your tool. (51:04-52:07) — opinion (biased: they sell Webflow work)
- [REF] Learning animations: collect a "personal internal encyclopedia" of references; practice by trying; trigger animations on a wrapper box around text rather than the text itself so the trigger does not move. (53:07-56:13) — practice
- [DS] Design systems matter once a Webflow site passes about 5-7 pages with CMS and animation; use atomic design (atoms, molecules), few combo classes, generic parent classes with combo modifiers (e.g. one "parent" with variants for blog card vs case-study card), and name classes consistently from the start. (1:00:18-1:06:31) — practice
- [BIZ] Outcome: site won a few awards (Mobile Excellence probably, not confirmed), the film-maker used it to become a brand ambassador for a bike company (caption "TRE", verify). (48:57-50:00) — evidence (maker's account)

## Techniques and steps
1. Pick one hero asset (here video) and design everything else to stay out of its way: black ground, quiet sans-serif, minimal UI. (9:11-11:15)
2. Custom cursor: two divs following the mouse via GSAP. (12:16)
3. Blink/shutter effect: CSS clip-path ellipse animation instead of Webflow interactions so it also works on mobile. (13:17)
4. Video pipeline: compress (HandBrake / Media Encoder) -> host on Vimeo Pro (direct link, 720/1080) -> play with Video.js styled by CSS overrides; lazy-load when many videos. (16:20-24:26)
5. Page transition: 200%-wide gradient box slid in, then rotated on next page load, with a JS delay on navigation. (28:29)
6. Responsive poster type: use vw units; clamp min and max; consider rem on mobile. (37:41)
7. Triggers: place animation triggers on a parent wrapper, not on the animated element. (55:10)
8. Class system for bigger sites: base class + combo class, generic naming. (1:03:26-1:06:31)

## Disagreements and contrarian points
Mild: Joe prefers HandBrake over Adobe tools for web video (17:21); maker still happy with Media Encoder. Panel disagrees slightly on how far to push fluid responsive type (39:44). On Webflow: the panel is openly partisan ("Editor X: blasphemy"), so any "Webflow is better" claims are opinion, not evidence.

## For 1000 Islands
Limited: our build is AI-assisted HTML, not Webflow, so tool tips mostly do not transfer. Transferable points: (1) restraint around the hero asset (for us, photography) with minimal UI; (2) video pipeline lessons if we use video: compress, host externally, lazy-load, sound off by default; (3) mobile browsers block autoplay audio and iPhone low-power mode blocks autoplay video, so always design a still poster fallback; (4) remove effects that cost performance and add nothing; (5) vw/clamp-based fluid type for poster-like headings with a mobile cap; (6) build early in the real medium (we already do HTML-first). The passion-project-with-no-sales-goal context is unlike our commercial site.
