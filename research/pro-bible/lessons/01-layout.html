    Урок 1. Как устроена страница

    После урока ты сможешь прочитать любую вёрстку от нейронки, назвать проблему правильным словом и за минуту проверить, развалится ли страница на телефоне.

    Примерно 50 минут. Девять интерактивов, в конце чек-лист приёмки и тест. Код писать не нужно: задача в том, чтобы понимать, что просить и как проверять.

    Пометки у утверждений: ◆ стандарт или первичный источник, ◈ согласие нескольких авторов или общая практика, ◇ мнение одного автора.

    Три слоя: смысл, вид, поведение

    Любая страница собрана из трёх языков. HTML говорит, что это такое: заголовок, абзац, кнопка, ссылка. CSS решает, как это выглядит и где стоит. JavaScript отвечает за то, что происходит после загрузки: открыть меню, проверить форму, подгрузить данные.

    Браузер читает HTML сверху вниз, строит из него дерево элементов (его называют DOM), накладывает CSS и рисует результат. Главная мысль раздела: если убрать CSS и JavaScript, должна остаться понятная страница с текстом и ссылками. Такую страницу прочитают поисковик, программа экранного доступа и человек на плохой связи. ◈ общая практика

    Выключи слои и посмотри, что останется

    Попробуй в обеих версиях выключить JavaScript. В первой жёлтый счётчик превратится в обычную строку и кнопка перестанет раскрывать блок, всё остальное на месте. Во второй останется белый лист. Ссылки внутри примера никуда не ведут, это макет.

    Где ошибаются нейронки

    • Без явного указания собирают обычный лендинг как React-проект с кучей файлов. ◇ DesignCode, Opus 5.5, сентябрь 2026; в другом видео Opus 4.6 сам выбрал обычный HTML (Flux, апрель 2026), так что поведение нестабильно
    • Ставят одинаковое появление снизу на каждый блок. ◈ Anthropic, Flux (Claude, май 2026) Если это появление держится на opacity: 0 и скрипте, получается ошибка из соседнего блока.

    Частые ошибки: у людей и у нейронок

    • В исходном HTML пустой <div id="root">, весь текст появляется только после выполнения скрипта. ◈ Fireship, Chrome
    • Контент спрятан через opacity: 0, пока скрипт не покажет. Скрипт упал, страница пустая. Даже если не упал, Chrome не считает невидимый элемент отрисованным, и метрика LCP ждёт скрипта. ◈ изменение Chromium 2020 по описанию DebugBear и Shopify; Impeccable
    • Кнопка с обработчиком там, где нужна обычная ссылка. ◈ Vercel, freeCodeCamp

    ◈ В наших источниках Fireship требует готовый HTML с сервера, а Chrome напоминает, что Googlebot умеет исполнять JavaScript. Безопасный вывод для сайта-визитки: отдавать готовый HTML. Проверка простая: открой исходный код страницы и найди там свой заголовок.

    Что сказать модели

    • Build this page as static HTML and CSS first. All text, links and images must be present in the HTML source.
    • JavaScript only enhances. If a script fails, content stays visible and links still work.
    • Do not hide content with opacity: 0 while waiting for a script to reveal it.

    Проверь за минуту

    Открой страницу, нажми Ctrl+U (View source) и поищи через Ctrl+F фразу с первого экрана. Нашлась: текст лежит в HTML. Не нашлась: его рисует скрипт.

    Всё на странице состоит из прямоугольников

    Каждый элемент браузер считает коробкой из четырёх слоёв: content (содержимое), padding (внутренний отступ), border (рамка) и margin (внешний отступ до соседей). Это называется box model. ◆ спецификация CSS

    Тонкость в том, что именно задаёт width. По старому правилу content-box ширина относится только к содержимому, а padding и border прибавляются сверху. По правилу border-box ширина уже включает padding и border. Поэтому почти каждый современный проект начинается со строки * { box-sizing: border-box }. ◈ общая практика

    Блок с width: 100% внутри экрана телефона
    content: текст, картинка, что угодно
    content padding border

    У margin есть странность. Вертикальные margin соседних блоков в обычном потоке не складываются, а схлопываются до большего из двух. Во flex и grid этого нет. ◆ спецификация CSS Отсюда практическое правило: расстояние между соседями задают через gap у родителя, а не раздают margin каждому ребёнку. ◈ практика

    Где ошибаются люди

    • Ставят width: 100% и добавляют padding. Блок становится шире родителя, страница начинает ездить вбок.
    • Раздают margin каждому элементу по отдельности. Отступы начинают спорить друг с другом, и никто не помнит, откуда взялись лишние 12 пикселей.

    Где ошибаются нейронки

    Отступы получаются неровными: сверху у блока одно расстояние, слева другое, между секциями то больше, то меньше. Anthropic пишет, что модели легко создают CSS-классы, которые гасят друг друга, особенно в отступах между секциями. В одном файле оказываются gap, margin-top, margin-bottom и пустые блоки-распорки, и через пять правок чинить это трудно. ◈ Anthropic; DesignCode (Opus 4.8, GPT-5.5, июнь 2026)

    Что сказать модели

    • Use box-sizing: border-box globally.
    • Space sibling elements with gap on the parent (flex or grid) instead of margins on children or empty spacer elements.
    • Take every spacing value from one scale defined as CSS custom properties.

    Проверь за минуту

    Правый клик по блоку, Inspect, вкладка Computed. Там нарисована схема коробки с числами. При наведении на элемент в дереве Chrome подсвечивает слои прямо на странице: синий content, зелёный padding, оранжевый margin. ◆ Chrome DevTools

    CSS это четыре разных способа расставлять блоки

    Самую полезную модель в голове хорошо формулирует Josh Comeau: CSS не один язык раскладки, а набор отдельных алгоритмов. Одно свойство на родителе переключает алгоритм для всех его детей. ◈ Comeau, 9elements

    • Flow, обычный поток. Работает по умолчанию. Блоки идут сверху вниз и занимают всю ширину, текст идёт в строку и переносится.
    • Flexbox, display: flex. Раскладывает детей вдоль одной оси: в ряд или в колонку.
    • Grid, display: grid. Сетка из строк и колонок, две оси сразу.
    • Positioned, position: absolute, fixed, sticky. Элемент вынимают из общего порядка и привязывают: к родителю, к окну или к краю при прокрутке.

    Одно и то же свойство в разных алгоритмах ведёт себя по-разному. width во flex это пожелание, а не приказ: блок сожмётся, если места нет. z-index в обычном потоке не работает вовсе. Когда «тот же самый код вдруг перестал работать», причина почти всегда в том, что элемент оказался в другом алгоритме.

    Что попробовать. Во Flex сузь контейнер без flex-wrap: блоки сначала сожмутся, потом вылезут за край. Включи flex-wrap, и они начнут переноситься сами. В Grid выбери auto-fit и двигай ширину: число колонок меняется без единого условия. В Absolute сузь контейнер: блоки стоят на своих координатах и наезжают друг на друга, им всё равно, сколько места вокруг.
    
  
    Правило выбора, на котором сошлись все пять авторов в нашей подборке: одна ось, значит Flex; две оси, значит Grid. Меню, ряд кнопок, иконка с подписью: Flex. Галерея карточек, макет страницы: Grid. ◈ Powell, Chrome, Comeau, midudev, Минин

    Во Flex каждый ряд считается отдельно, поэтому остаток растягивается на всю ширину и карточки получаются разного размера. Grid держит общие колонки для всех рядов. На узком экране разницы не видно: открой на широком.
    
  
    

  
    
    
    Где ошибаются нейронки
    
    
    Если отдать модели макет из Figma без auto layout, она видит набор абсолютных координат и повторяет их через position: absolute и фиксированные пиксели. На другой ширине всё наезжает. ◇ Flux, Opus 4.6, апрель 2026, совет, а не показанный результат
    
  
    
  
    
    
    Частые ошибки: у людей и у нейронок

      • 
      
    • position: absolute для обычной раскладки, чтобы «точно попасть в макет». ◈ Comeau

    Что сказать модели

      •

      • 
      
    • Never use position: absolute for layout, only for small decorative overlays.

    Проверь за минуту
    
    
    В DevTools рядом с элементом в дереве стоят значки flex и grid. Клик по значку рисует линии сетки поверх страницы: сразу видно, сколько колонок и где промежутки. ◆ Chrome DevTools
    
  
    

    


    
  
    Ширина смотрит вверх, высота смотрит вниз
    
  
    В обычном потоке ширину блок берёт у родителя: сколько дали, столько и займу. Высоту он берёт у содержимого: сколько текста внутри, такой я высоты. Это наследство бумажного документа, где у листа фиксированная ширина, а страниц может быть сколько угодно. ◈ Comeau
    
  
    Отсюда два правила Kevin Powell, которые снимают большую часть проблем адаптива. ◈ Powell
    
  
      
    
    • Блокам с текстом не задают height. Если нужна минимальная высота, это min-height.
      • 
    
    • Контейнерам не задают width. Задают max-width, чтобы блок мог сжиматься.
      • 
  
    
  
    И его же наблюдение: голый HTML адаптивен сам по себе. Если страница ломается на телефоне, значит, её сломал CSS, который мы написали.

    Увеличь длину текста при height: 180px. Цена сначала выползает из карточки поверх соседнего блока. Включи overflow: hidden: теперь цена просто исчезла, а это хуже, потому что ошибку не видно. С min-height карточка растёт вместе с текстом.
    

  
    Ловушка 100vh на телефоне
    
  
    Первый экран часто просят сделать «во всю высоту» и пишут height: 100vh. На телефоне это высота окна без панелей браузера. Пока адресная строка видна, блок получается выше видимой области, и его низ вместе с кнопкой уезжает под панель. Для этого появились новые единицы. ◆ спецификация CSS, ◈ Comeau
    

  
    
    
    
      
    адресная строка
    
      
    то, что человек видит сразу
    
      
    панель браузера
    
    
    
    
    
      
    100vh
    
      
    100svh
    
    
    
    
      
      
    • 100vh: вся высота экрана, как будто панели уже спрятаны. Больше, чем видно при открытии.
      • 
      
    • 100svh (small): высота с показанными панелями. Ровно то, что человек видит сразу.
      • 
      
    • 100dvh (dynamic): подстраивается, когда панели прячутся при прокрутке.
      • 
    
    
  
    

  
    
    
    Частые ошибки: у людей и у нейронок
    
    
      
      
    • Фиксированные высоты у первого экрана и карточек: h-[600px], height: 100vh. ◈ Powell, midulive
      • 
      
    • Одинаковая высота карточек через height, хотя Grid и так растягивает карточки в ряду до самой высокой. ◈ практика
      • 
      
    • overflow: hidden на блоке фиксированной высоты: длинный текст обрезается молча. Сам line-clamp нормален, Vercel советует его для длинного текста, но только если полный текст можно прочитать где-то ещё. ◆ Vercel
      • 
    
    
  
    
  
    
    
    Что сказать модели
    
    
      
      
    • No fixed heights on anything that contains text; use min-height.
      • 
      
    • Page containers: max-width plus margin-inline: auto, never a fixed width.
      • 
      
    • Hero: min-height: 100svh, not height: 100vh.
      • 
      
    • The layout must survive headings and labels twice as long as the sample copy.
      • 
    
    
  
    
  
    
    
    Проверь за минуту
    
    
    Попроси модель временно подставить заголовок вдвое длиннее и название тура на немецком, потом посмотри страницу на ширине 320. Всё, что вылезло или обрезалось, стояло на фиксированных размерах.
    
  
    

    


    
  
    В чём измеряют: px, rem, проценты и остальные
    
  
    
    
    px
    Фиксированный размер. Годится для рамок и мелких деталей.
    
    
    rem
    Доля от базового размера шрифта страницы. По умолчанию 1rem равен 16px. ◆ значение по умолчанию в браузерах
    
    
    em
    Доля от размера шрифта самого элемента. Удобно для отступов внутри кнопки.
    
    
    %
    Доля от родителя.
    
    
    vw, vh
    Доля от окна. Применять осторожно.
    
    
    ch
    Ширина символа «0». Удобно для текстовой колонки: max-width: 65ch.
    
    
    fr
    Доля свободного места в Grid.
    
  
    
  
    Согласие авторов: размеры шрифта и отступы в rem, ширины в процентах, fr и через max-width. ◈ Powell, Chrome, Comeau, midudev, Минин Шрифт в пикселях плох тем, что игнорирует настройку человека, который увеличил текст в браузере.
    

  
    
    
    Человек увеличил шрифт в настройках браузера
    
    
    
      
    
    
    
    
    Левая карточка свёрстана в px и не реагирует: человеку с плохим зрением она так и останется мелкой. Правая в rem: текст, отступы и кнопка растут вместе.
    
  
    

  
    Ещё один инструмент, clamp(). Запись font-size: clamp(2rem, 6vw, 4rem) значит: не меньше 2rem, не больше 4rem, а между ними расти вместе с окном. Заголовок меняется плавно без единого условия. Потрогаешь в следующем разделе.
    

  
    
    
    Частые ошибки: у людей и у нейронок
    
    
      
      
    • Размеры шрифта в пикселях: font-size: 14px, text-[13px]. ◈ пять авторов; ◆ WCAG 1.4.4
      • 
      
    • width: 100vw у секций. На Windows 100vw включает полосу прокрутки, блок выходит шире страницы на её ширину, и появляется горизонтальный скролл. ◈ Powell
      • 
    
    
  
    
  
    
    
    Что сказать модели
    
    
      
      
    • Font sizes and spacing in rem.
      • 
      
    • No 100vw widths; block elements are full width by default.
      • 
      
    • Fluid headings with clamp(min, preferred, max).
      • 
    
    
  
    

    


    
  
    Адаптив: одна страница на любую ширину
    
  
    Сайт открывают на экранах шириной от 320 до 2500 пикселей. Отдельных версий никто не делает: один HTML и CSS, который перестраивает блоки. Три приёма по убыванию важности. ◈ Powell, Chrome, Comeau
    
  
      
    
    1. Резиновая основа. max-width, проценты, flex-wrap, Grid с auto-fit, clamp(). Блоки сами занимают доступное место. Jen Simmons назвала это intrinsic design.
      2. 
    
    2. Mobile first. Базовые стили описывают узкий экран, где всё в одну колонку. @media (min-width: …) добавляет сложность там, где появилось место.
      3. 
    
    3. Точки перелома по содержимому. Breakpoint ставят там, где контенту стало тесно, а не под конкретную модель телефона.
      4. 
  
    
  
    Одна строка в <head> обязательна: <meta name="viewport" content="width=device-width, initial-scale=1">. Без неё телефон рисует страницу как на широком мониторе и уменьшает. И никогда не запрещать человеку зум: user-scalable=no и maximum-scale=1 в списке запретов. ◆ Vercel Web Interface Guidelines

    В первой версии всё задано в пикселях под монитор: контейнер 1100, заголовок 64, карточки по 340. На 390 страница едет вбок. Вторая версия показывает любимое «лечение»: скролл исчез, но две карточки из трёх стали недоступны. Третья собрана из max-width, auto-fit и clamp(): в ней нет ни одного media query.
    

  
    Найди, кто торчит
    
  
    Горизонтальный скролл почти всегда даёт один конкретный элемент. Искать его глазами долго. Приём простой: обвести все блоки рамкой и посмотреть, чей край вышел за экран.

    • Прячут горизонтальный скролл через overflow-x: hidden на body и не ищут, что именно вылезает. Vercel советует сначала найти и исправить переполнение. ◆ Vercel
      • 
      
    • Забывают промежуток между 768 и 1024: планшет получает либо растянутый телефон, либо сжатый монитор. ◇ Impeccable
      • 
      
    • Наведение мышкой как единственный способ увидеть информацию. На телефоне наведения нет. ◈ Vercel, Impeccable
      • 
    
    
  
    
  
    
    
    Что сказать модели
    
    
      
      
    • Mobile-first CSS: base styles for narrow screens, min-width media queries only add complexity.
      • 
      
    • Prefer intrinsic layout (flex-wrap, grid auto-fit, clamp) over breakpoints.
      • 
      
    • No horizontal scroll at 320, 390, 768, 1024 and 1440 px. Do not use overflow-x: hidden to hide overflow; find and fix the element that causes it.
      • 
      
    • img, video { max-width: 100%; height: auto }
      • 
    
    
  
    
  
    
    
    Проверь за минуту
    
    
    F12, затем Ctrl+Shift+M: откроется режим устройства. Поставь ширину 320 и попробуй прокрутить вбок. Потом возьми за край и медленно тяни от 320 до 1440, глядя, где что-то ломается. Ломается обычно не на «круглых» ширинах, а между ними.
    
  
    

    


    
  
    Что лежит поверх чего
    
  
    Свойство position вынимает элемент из общего порядка.
    
  
      
    
    • relative: элемент остаётся на месте, но становится точкой привязки для вложенных absolute.
      • 
    
    • absolute: вынут из потока и привязан к ближайшему предку с position. Если такого нет, к странице. ◆ спецификация CSS
      • 
    
    • fixed: привязан к окну. У Comeau хороший образ: жук на стекле поезда. Пейзаж едет, жук на месте.
      • 
    
    • sticky: ведёт себя как обычный блок, пока не доедет до края окна, потом прилипает.
      • 
  
    
  
    Порядок по глубине задаёт z-index, и здесь главная ловушка. Числа сравниваются не по всей странице, а внутри своего контекста наложения, stacking context. Comeau объясняет через номера версий: если у родителя z-index 1, то ребёнок с 9999 это версия 1.9999. Она всегда меньше, чем 2.0 у соседнего блока. ◈ Comeau

    Где ошибаются нейронки
    
    
    Заголовок и подпись наезжают на картинку, на другой ширине декоративные элементы ложатся на текст. Исправлялось отдельной просьбой. ◇ DesignCode (модели в Aura, май–июнь 2026)
    
  
    
  
    
    
    Частые ошибки: у людей и у нейронок
    
    
      
      
    • Фиксированные панели, которые на телефоне закрывают контент и поле, в котором стоит курсор. ◆ Vercel
      • 
      
    • Всплывающее окно, под которым продолжает прокручиваться страница. По стандарту всё под модальным окном должно быть неактивно. ◆ W3C WAI-ARIA APG; ◆ Vercel
      • 
    
    
  
    
  
    
    
    Что сказать модели
    
    
      
      
    • Absolute positioning only for decoration that overlaps nothing important at any width.
      • 
      
    • Keep a z-index scale as CSS custom properties (--z-header, --z-overlay, --z-modal) and avoid arbitrary values like 9999.
      • 
      
    • Add scroll-margin-top to anchored headings, equal to the sticky header height.
      • 
      
    • Sticky or fixed bars must never cover content, form fields or the focused element on mobile.
      • 
    
    
  
    

    


    
  
    Теги со смыслом: что видит машина
    
  
    Два блока могут выглядеть одинаково и при этом быть совсем разными для всех, кто читает страницу не глазами: поисковика, программы экранного доступа, клавиатуры и самой нейронки, когда она вернётся править код. Они читают теги. ◈ все авторы по доступности и SEO
    
  
      
    
    • Каркас: header, nav, main, footer.
      • 
    
    • Заголовки h1–h6: один h1 на страницу, уровни идут по порядку, без пропусков.
      • 
    
    • Действие это <button>. Переход это <a href>. Не div с обработчиком. ◆ Vercel Web Interface Guidelines
      • 
  
    
  
    Частая путаница: уровень заголовка выбирают по структуре, а размер задают стилем. У Sajid это одна фраза: code for document hierarchy, style for visual hierarchy. Заголовок второго уровня может быть мелким, если так нужно дизайну. ◇ Sajid
    

  
    
    
    
      На вид одинаково. А для машины?
      
    
        
        
      
    
    
    
    
    
      
    
        
        
    
      
    
    
    
    
    Кликни внутрь примера и понажимай Tab. В версии из div фокус не попадает ни на «ссылки», ни на «кнопку»: с клавиатуры ими воспользоваться нельзя.
    
  
    

  
    
    
    Где ошибаются нейронки
    
    
      
      
    • Уровни заголовков по размеру шрифта, а не по структуре: проверка axe нашла h4 там, где должен быть h2. ◇ Brad Frost, Sonnet 4.5, декабрь 2025; у моделей 2024–2025 то же в рецензируемом исследовании W4A 2025
      • 
      
    • Кнопки и картинки без имени: аватары без подписи, звёзды рейтинга без aria-label. Машина видит «кнопка» и ничего больше. ◇ Flux, аудит страницы Claude, май 2026
      • 
    
    
    
    Оба наблюдения сделаны на моделях постарше. В бенчмарке AIMAC (октябрь 2026) пустые кнопки есть только на 4% страниц всех моделей, а порядок заголовков он не меряет. Подробнее в уроке 4.
    
  
    
  
    
    
    Частые ошибки: у людей и у нейронок
    
    
      
      
    • <div onclick> вместо кнопки и ссылки. ◈ Vercel, Osmani
      • 
      
    • Три h1 на странице. ◈ freeCodeCamp, Web Dev Simplified
      • 
    
    
  
    
  
    
    
    Что сказать модели
    
    
      
      
    • Semantic HTML: one h1, sequential heading levels, landmarks (header, nav, main, footer).
      • 
      
    • Use button for actions and a[href] for navigation, never a div or span with a click handler.
      • 
      
    • Icon-only buttons need an aria-label. Every image needs alt (empty alt for decorative ones).
      • 
    
    
  
    
  
    
    
    Проверь за минуту
    
    
    Положи руки на клавиатуру и пройди страницу одним Tab. Всё, на что можно нажать мышкой, должно получать видимую рамку фокуса и срабатывать по Enter.
    
  
    

    


    
  
    Двенадцать типичных ошибок вёрстки у нейронок
    
  
    Шпаргалка по разделам выше. По каждой: как это выглядит и какой фразой чинить. ◈ собрано из разделов урока и запретов в скиллах Vercel и Impeccable
    
  
      
    
    1. 1. Фиксированная высота у блока с текстом
      Текст вылезает поверх соседей или обрезается.
      Use min-height, never height, on text containers.
      2. 
    
    2. 2. height: 100vh у первого экрана
      На телефоне кнопка внизу прячется под панель браузера.
      Use min-height: 100svh.
      3. 
    
    3. 3. width: 100vw
      Горизонтальный скролл на Windows.
      Remove it; blocks are full width by default.
      4. 
    
    4. 4. overflow-x: hidden на body
      Скролла нет, но часть контента недоступна. Может сломать sticky.
      Find the overflowing element and fix the cause.
      5. 
    
    5. 5. Раскладка на position: absolute
      На другой ширине блоки наезжают друг на друга.
      Use grid or flex for layout.
      6. 
    
    6. 6. Сетка карточек на процентах
      Рваные ряды, карточки разного размера.
      Use grid with auto-fit and minmax.
      7. 
    
    7. 7. Десять условий max-width
      Каждая правка ломает какую-то ширину.
      Rewrite mobile-first with intrinsic layout.
      8. 
    
    8. 8. Шрифт в пикселях
      Не реагирует на настройку размера текста в браузере.
      Font sizes in rem.
      9. 
    
    9. 9. Картинка без ограничений
      Фото выпирает за экран или сплющено.
      max-width: 100%; height: auto; set aspect-ratio and object-fit: cover.
      10. 
    
    10. 10. Карточка в карточке в карточке
      Рамки внутри рамок, полезного места почти нет. ◆ Impeccable
      Flatten: no nested cards.
      11. 
    
    11. 11. z-index: 9999
      Не помогает и плодит новые конфликты.
      Use a z-index scale; check stacking contexts.
      12. 
    
    12. 12. div вместо button и a
      С клавиатуры не работает, машины не понимают.
      Use semantic elements for anything clickable.
      13. 
  
    

    


    
  
    Словарь, чтобы называть вещи точно
    
  
    Чем точнее слово в запросе, тем меньше модель додумывает. Эти термины встречаются чаще всего.
    
  
    
    
    viewport
    Видимая область окна браузера.
    
    
    breakpoint
    Ширина, на которой раскладка перестраивается.
    
    
    container, wrapper
    Блок, который ограничивает ширину контента и центрирует его.
    
    
    gutter
    Поле между контентом и краем экрана.
    
    
    gap
    Промежуток между соседями во flex и grid.
    
    
    overflow
    Содержимое, которое не поместилось в блок.
    
    
    hero
    Первый большой блок страницы.
    
    
    above the fold
    То, что видно без прокрутки.
    
    
    intrinsic, fluid
    Раскладка, которая подстраивается сама, без условий.
    
    
    stacking context
    Группа, внутри которой сравниваются z-index.
    
    
    DOM
    Дерево элементов, которое браузер строит из HTML.
    
    
    landmark
    Смысловая область страницы: шапка, навигация, основная часть, подвал.
